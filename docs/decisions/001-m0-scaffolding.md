# 001: M0 scaffolding choices

Status: accepted (slice 1, milestone M0)

## Context

Slice 1 §2 and CLAUDE.md describe the scaffold but leave some details open.

## Decision

- **Deep sea colour** is `#0b1a2e`, the "deep sea" UI token from spec §9. It is used for
  `theme-color`, the page background and the empty canvas. It is defined once in
  `render/palette.ts` and as `--deep-sea` in CSS.
- **The project files were written by hand** instead of generated by
  `npm create vite`, because the directory was not empty. They match the vanilla-ts
  template minus its demo content.
- **Toolchain versions:** Vite 8, Vitest 5, ESLint 10 and TypeScript 6.0.
  typescript-eslint 8 supports TypeScript `<6.1`, so TypeScript stays on 6.0.x until it
  catches up. `engines.node` is `^22.13.0 || >=24` because ESLint 10 declares that
  range. CI uses Node 22.
- **Placeholder modules:** `sim/rng.ts`, `sim/time.ts` and `render/camera.ts` exist
  only as `export {}` with a pointer to the spec section that fills them. No logic is
  built ahead of its milestone.
- **M0 canvas:** a plain full-window canvas at device-pixel resolution. The low-res,
  integer-scaled view (spec §8.1) arrives in M2.
- **Loop:** the accumulator arithmetic is a pure `advance()` function in
  `game/loop.ts`, so the 1/60 s step and the 250 ms clamp can be unit tested without
  a browser.
- **Claude Code permissions:** `git push`, `rsync`, `ssh`, `scp` and the deploy script
  are in the `ask` list. They always prompt, even if a broader allow rule is added
  later, and deliberate manual use stays possible.
- **Prettier** ignores `CLAUDE.md` and `docs/`, so `npm run format` never rewrites the
  hand-written specs. `npm run check` does not include a format check, following
  CLAUDE.md's definition.

## Consequences

Upgrading TypeScript to 7 waits for typescript-eslint support. Contributors on odd
Node releases (such as 23) will see engine warnings from npm.
